# 家庭聯絡簿「教師叮嚀」欄

紙本「家庭聯絡暨學習紀錄」中，到校情形、精神狀態、今日學習表現等**皆為勾選欄**，
由教師人工勾選，不在本流程範圍。唯一需要撰寫的是「**教師叮嚀**」欄（8.5cm × 5cm）。

本 skill 依教師口述之當日概況，展開為可直接謄寫、或列印裁切後黏貼的文字。

## 為什麼這件事值得一套流程

教師每天要為全班逐一構思措辭，這是重複性高、但又不能敷衍的工作。
把「語氣規範、篇幅限制、資料來源、版面參數」固定下來，教師就只需要口述當天發生的事，
其餘交給流程。流程本身必須可靠——2026-09-22 曾有兩次任務耗時共 2 小時 42 分、
其中一次產出的 .docx 無法開啟，本 skill 的每一條設計都對應當時的一項失效。

| 來源 | 內容 | 取得方式 |

## 二、行事曆與課表的使用時機

先查這兩項，但**不是查到什麼就寫什麼**。

| 情境 | 處理方式 |
|---|---|
| 行事曆當天有**特殊活動** | 可寫入（例：園藝治療課程開始、防災演練、藝文巡演） |
| 教師口述**有提到科目** | 以個人課表**核對正式名稱與節次**後寫入 |
| 教師未提科目、當天也無特殊活動 | **不主動列出例行課程** |

**不主動複述課表的理由**：每天都寫「今日有農園藝實作」對家長沒有資訊量，
而且會吃掉單格僅有的 96 字額度。家長想知道的是「今天我的孩子怎麼樣」，
不是「今天課表上有什麼」。課表的用途是**核對與正名**。

**課表的核對價值**：教師口述常用簡稱。教師說「語文課」，個人課表顯示該生為
「國語文 C 組」，寫入時即可精確為「今日國語文分組課程」。
各生分組不同——同一節課，甲生在數學 A 組、乙生在 B 組——
所以逐生內容要查**個人**課表，只看班級課表會寫錯。

**兩者互補的實例**：班級課表顯示某週二第 2–4 節為「農園藝種植維護實作」（常態科目），
行事曆則記載當天「園藝治療課程開始」（外聘治療師入班的特殊安排）。
只查課表會漏掉當天真正值得告訴家長的事；只查行事曆則寫不出正確的節次脈絡。

## 三、內容結構

```
〔名〕今日表現：（質性敘述句：科目/活動 ＋ 具體表現）
（可選：第 2 句質性敘述或全校性活動說明）

1.（列點提醒事項，如需家長配合之具體行動）
2.（若有第 2 項提醒）
```

- **質性敘述句**：具體課堂活動 ＋ 該生表現，語氣溫和口語
- **列點提醒事項**：需家長配合的具體行動，以 `1.` `2.` 編號

## 四、語氣規範

| 項目 | 規範 |
|---|---|
| 適用規則 | 依 `.claude/rules/sped/parent-comm.md` 溫和同理原則 |
| **不**適用 | `writing-rules.md` 規則二（IEP 臨床中立語氣、禁讚美語） |
| 開頭格式 | 固定為「〔名〕今日表現：」，名字取學生本名之「名」（不含姓）；不使用「個案」代稱 |
| 篇幅 | 約 3–5 行、含標點 60–95 字（不含開頭字數）；單格上限 96 字 |
| 隱私 | 涉及其他學生時不具名 |
| 內容依據 | 僅依教師口述展開，不臆測未發生的課堂細節；行事曆／課表只用於補正事實 |

**關於語氣例外**：聯絡簿是親師溝通文件，可以用「表現不錯」「配合度高」這類溫和用語。
這與 IEP 目標所要求的臨床中立語氣**刻意不同**，是設計，不是疏漏。
若日後有人依慣性拿 IEP 規則來審查聯絡簿產出，這一條就是說明。

## 五、逐格獨立（最容易出錯的一條）

**每位學生的內容都是獨立交付給該生家長的一格。** 家長看不到其他格，
因此任何需要參照其他格才能讀懂的敘述，對家長而言都是斷裂的。

| ❌ 錯誤 | 為什麼 | ✅ 改寫 |
|---|---|---|
| 「**同樣**不太喜歡拔草工作」 | 「同樣」指涉的是另一格的學生；該生家長無從得知在跟誰同樣 | 「較不喜歡拔草工作」 |
| 「表現**最為**積極」 | 最高級隱含與同學比較 | 「整理菜圃與繪製時都相當專注」 |
| 「**跟同學一樣**喜歡畫畫」 | 以他人為參照點 | 「喜歡畫畫」 |
| 「**其他同學**都完成了」 | 直接提及其他學生 | 刪除，或只寫該生自身進度 |

「在老師與**同學**協助下順利完成」屬**正常敘述**——描述的是該生獲得的支持方式，
單獨閱讀即可理解，不在禁止之列。

產生器會在產出前攔下明確的跨生指涉，並對「最為」等比較語發出提示。
但關鍵詞比對讀不懂語意——像「今天終於也願意嘗試了」這種隱含對照的句子抓不到，
所以**寫完仍要把每一格單獨讀一遍**，確認不靠其他格也讀得懂。

## 六、範例（去識別化，一律以 S 代號呈現）

**只有課堂表現**
```
S01今日表現：本土語文課，跟著老師一起學台語說自己的名字，表現不錯。
```

**課堂表現 ＋ 家長配合事項**
```
S02今日表現：今日參與語文分組課程。

1. 麻煩將外套帶回學校，以便協助烘乾。
```

**全校性活動（來自行事曆）**
```
S03今日表現：認識並參與國際防災日，完成地震避難演練。
```

**口述內容簡短時**（不勉強擴充）
```
S07今日表現：今日情緒穩定，各節課皆能跟隨班級作息。
```

正式產出時，`S01` 等代號替換為學生本名之「名」。
本 skill 的所有文件一律只出現 S 代號，學生真名只出現在交付給教師的產出中。

## 七、輸出形式

### 7.1 逐則文字
直接於對話中列出，供教師謄寫或核對。

### 7.2 列印裁切表格（.docx）

**一律使用 `scripts/build_contact_book.py`。**

```bash
pip3 install python-docx
python3 scripts/build_contact_book.py entries.json -o 家庭聯絡簿_教師叮嚀欄_YYYYMMDD.docx
```

`entries.json`（格式範例見 `references/entries.example.json`）：
```json
[{"label": "S01", "text": "今日參與語文分組課程。\n\n1. 麻煩將外套帶回學校。"}]
```

| 版面參數 | 值 |
|---|---|
| 表格 | 2 欄 × 4 列（8 格） |
| 每格 | 8.5cm × 5cm（列高 exact，裁切後尺寸精確） |
| 字體 | 標楷體 14pt，行高 20pt |
| 頁面 | A4 直向，邊界 1.5cm |
| 單格容量 | 約 96 字（6 行 × 16 字） |

不足 8 筆時其餘格留白。產生器會先檢查逐格獨立性（發現跨生指涉即阻擋輸出），
再驗證 ZIP 結構、OOXML schema 順序與欄寬列高，任一項失敗即以非零狀態離開。
要改版面只改 `LAYOUT` 這個 dict，不要改散落各處的數字。

### 7.3 兩種絕對禁止的做法

兩者都曾實際造成 Word 無法開啟，而且**檔案大小與 ZIP 結構看起來都正常**，
所以光看「檔案有產出、大小合理」驗不出問題：

1. **讓模型在對話上下文中逐字搬運 base64**。Read 讀取無換行長檔會靜默截斷；
   即使分段重組，單字元誤植即造成 ZIP CRC 損毀，而檔案大小仍吻合。
   正確做法是讓腳本直接把檔案寫到磁碟，位元組永遠不經過模型的上下文。
2. **手工拼接 `word/document.xml`，把元素 append 到 `w:tblPr` 尾端**。
   `w:tblPr` 是有序序列（ECMA-376 CT_TblPrBase）且多數子元素不可重複；
   違反時 Word 判定「內容無法讀取」而拒絕開啟。LibreOffice 與 Google Drive
   的容忍度不同，所以「某個閱讀器打得開」不能當作驗證通過。

### 7.4 存放路徑
`特教工作區 → 班級_118級乙班 → _CLASS-班務 → 聯絡簿`
檔名：`家庭聯絡簿_教師叮嚀欄_YYYYMMDD.docx`

## 八、執行步驟

1. 接收教師當日口述（逐生或全班批次）
2. **查行事曆**：列出當日該班的特殊活動（無則略過）
3. **查課表**：教師口述提及科目時，以個人課表核對正式名稱、節次與分組
4. 資訊不足時**直接詢問教師**，不臆測
5. 依第三節結構展開、第四節語氣規範潤飾，依第二節決定是否寫入活動／科目
6. **逐格自我檢查**：把每一格單獨讀一遍，確認不需要其他格就能理解
7. 輸出逐則文字供教師確認
8. 需列印表格時，寫 `entries.json` → 執行產生器 → 確認驗證通過
9. 交付檔案，並存入 7.4 的路徑

## 九、品質檢核

| 項目 | 標準 |
|---|---|
| 篇幅 | 3–5 行、60–95 字，未超出 96 字上限 |
| 開頭格式 | 以「〔名〕今日表現：」開頭 |
| 內容具體 | 避免「今天表現很好」這類籠統敘述 |
| 語氣 | 溫和、無專業術語，家長能直接理解 |
| 提醒可執行 | 需家長配合事項寫出具體動作 |
| 未臆測 | 僅依教師口述展開 |
| 科目正名 | 有提及科目時，名稱與分組與個人課表一致 |
| 逐格獨立 | 無跨生指涉；單獨閱讀該格即可理解 |
| .docx 有效性 | 產生器 `verify()` 全數通過 |
