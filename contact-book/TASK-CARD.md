## 一、任務定義

紙本「家庭聯絡暨學習紀錄」中，到校情形、精神狀態、今日學習表現等**皆為勾選欄**，
由教師人工勾選，不在本流程範圍。唯一需要撰寫的是「**教師叮嚀**」欄
（8.5cm × 5cm）。本流程依教師口述之當日概況，展開為可直接謄寫或列印裁切的文字。

---

## 二、輸入來源與可用性

| 來源 | 內容 | 取得方式 | 雲端 session 可用？ |
|---|---|---|:-:|
| 教師口述 | 當日該生重點 | 對話中直接提供，逐生或全班批次皆可 | ✅ |
| 個案概況 | 能力現況、慣用支持方式 | H: 側 `00-個案總覽.md` | ❌ |
| 當日課表 | 各節次科目 | H: 側班級／個人課表 | ❌ |
| 全校性活動 | 防災日、運動會等 | **僅依教師口述提及才寫**，不主動查外部行事曆 | — |

> ⚠️ **H: 側輸入僅在家機／校機 session 可用。**
> Claude Code on the web 的容器沒有 H: 磁碟，請勿嘗試掃描或猜測路徑——
> 雲端 session 一律改為**直接向教師詢問**所需資訊。
> （2026-09-22 兩次 session 的耗時，部分即來自在雲端反覆尋找 H: 側檔案。）

## 三、內容結構

```
〔名〕今日表現：（質性敘述句：科目/活動 ＋ 具體表現）
（可選：第 2 句質性敘述或全校性活動說明）

1.（列點提醒事項，如需家長配合之具體行動）
2.（若有第 2 項提醒）
```

- **質性敘述句**：具體課堂活動 ＋ 該生表現，語氣溫和口語
- **列點提醒事項**：需家長配合的具體行動，以 `1.` `2.` 編號

## 四、語氣規範

| 項目 | 規範 |
|---|---|
| 適用規則 | 依 `.claude/rules/sped/parent-comm.md` 溫和同理原則 |
| **不**適用 | `writing-rules.md` 規則二（IEP 臨床中立語氣、禁讚美語）。**此為刻意例外**，非疏漏——聯絡簿是親師溝通文件，可用「表現不錯」「配合度高」 |
| 開頭格式 | 固定為「〔名〕今日表現：」，名字取學生本名之「名」（不含姓）；不使用「個案」代稱 |
| 篇幅 | 約 3–5 行、含標點 60–95 字（不含開頭字數）。產生器實測單格上限 96 字 |
| 隱私 | 涉及其他學生時不具名 |
| 內容依據 | **僅依教師口述展開，不臆測未發生的課堂細節** |
| **逐格獨立** | **每格須能脫離其他格獨立閱讀**——家長只會收到自己孩子那一格。禁止「同樣」「跟同學一樣」「其他同學」「相較」「比…更」等跨生指涉，也不得與同學比較優劣。詳見第五節之二 |

---

## 四之二、逐格獨立（2026-09-22 教師指示）

**每位學生的內容都是獨立交付給該生家長的一格。**家長看不到其他格，
因此任何需要參照其他格才能讀懂的敘述，對家長而言都是斷裂的。

| ❌ 錯誤 | 為什麼 | ✅ 改寫 |
|---|---|---|
| S05：「**同樣**不太喜歡拔草工作」 | 「同樣」指涉的是前一格另一位學生；該生家長無從得知在跟誰同樣 | 「較不喜歡拔草工作」 |
| S02：「表現**最為**積極」 | 最高級隱含與同學比較 | 「整理菜圃與繪製時都相當專注」 |
| 「**跟同學一樣**喜歡畫畫」 | 以他人為參照點 | 「喜歡畫畫」 |
| 「**其他同學**都完成了」 | 直接提及其他學生 | 刪除，或只寫該生自身進度 |

> 「在老師與**同學**協助下順利完成」屬**正常敘述**——描述的是該生獲得的支持方式，
> 不需要其他格的資訊即可理解，不在禁止之列。

產生器會在**產出前**攔下明確的跨生指涉（`check_independence`），
並對「最為」等比較語發出提示，交由教師判斷。

## 五、範例（去識別化，一律以 S 代號呈現）

**只有課堂表現**
```
S01今日表現：本土語文課，跟著老師一起學台語說自己的名字，表現不錯。
```

**課堂表現 ＋ 家長配合事項**
```
S02今日表現：今日參與語文分組課程。

1. 麻煩將外套帶回學校，以便協助烘乾。
```

**全校性活動**
```
S03今日表現：認識並參與國際防災日，完成地震避難演練。
```

**口述內容簡短時**（不勉強擴充）
```
S07今日表現：今日情緒穩定，各節課皆能跟隨班級作息。
```

> 正式產出時，`S01` 等代號替換為學生本名之「名」。
> **本檔與所有 G: 側規範文件一律只出現 S 代號**（依 `PROJECT-INSTRUCTIONS.md` 資料分界）。

## 六、輸出形式

### 6.1 逐則文字
直接於對話中列出，供教師謄寫或核對。

### 6.2 列印裁切表格（.docx）

**一律使用固定產生器，不得手工組裝 OOXML、不得由模型搬運檔案位元組。**

```bash
python3 contact-book/build_contact_book.py entries.json -o 家庭聯絡簿_教師叮嚀欄_YYYYMMDD.docx
```

`entries.json`：
```json
[{"label": "S01", "text": "今日參與語文分組課程。\n\n1. 麻煩將外套帶回學校。"}]
```

| 版面參數 | 值 |
|---|---|
| 表格 | 2 欄 × 4 列（8 格） |
| 每格 | 8.5cm × 5cm（列高 exact，裁切後尺寸精確） |
| 字體 | 標楷體 14pt，行高 20pt |
| 頁面 | A4 直向，邊界 1.5cm |
| 單格容量 | 約 96 字（6 行 × 16 字） |

不足 8 筆時其餘格留白。產生器會自動驗證 ZIP 結構、OOXML schema 順序與欄寬列高，
並對超出 96 字的內容發出篇幅警告。

**❌ 絕對禁止的做法**（皆曾實際造成檔案無法開啟）：
- 讓模型在對話上下文中逐字搬運 base64 → Read 會靜默截斷，且單字元誤植會造成
  「ZIP CRC 損毀但檔案大小吻合」的無聲失敗
- 手工拼接 `word/document.xml` 並把元素 append 到 `w:tblPr` 尾端 →
  `w:tblPr` 是**有序序列**且多數子元素不可重複，違反時 Word 判定「內容無法讀取」

### 6.3 存放路徑
`特教工作區 → 班級_118級乙班 → _CLASS-班務 → 聯絡簿`（H: 側）
檔名：`家庭聯絡簿_教師叮嚀欄_YYYYMMDD.docx`

> 📌 產出**確實落地存檔**（供列印裁切使用）。
> v1.1 曾記載「不落地存檔」，該敘述已於本版更正。

## 七、品質檢核

| 項目 | 標準 |
|---|---|
| 篇幅 | 3–5 行、60–95 字，未超出 96 字上限 |
| 開頭格式 | 以「〔名〕今日表現：」開頭 |
| 內容具體 | 避免「今天表現很好」這類籠統敘述 |
| 語氣 | 溫和、無專業術語，家長能直接理解 |
| 提醒可執行 | 需家長配合事項寫出具體動作 |
| 未臆測 | 僅依教師口述展開 |
| **逐格獨立** | 無跨生指涉；單獨閱讀該格即可理解（產生器自動攔阻） |
| **.docx 有效性** | 產生器 `verify()` 全數通過（ZIP + schema + 尺寸） |

## 八、執行步驟

1. 接收教師當日口述（逐生或全班批次）
2. 資訊不足時**直接詢問教師**；雲端 session 不嘗試存取 H: 側
3. 依第三節結構展開、第四節語氣規範潤飾
4. 輸出逐則文字供確認
5. 需列印表格時，寫 `entries.json` → 執行產生器 → 確認驗證通過
6. 交付檔案，並存入第 6.3 節路徑
